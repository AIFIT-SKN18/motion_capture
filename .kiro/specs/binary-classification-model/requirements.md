# Requirements Document

## Introduction

이 문서는 기존 MS-G3D 기반 운동 동작 분류 모델과 함께 사용할 이진분류 모델 선택 및 통합에 대한 요구사항을 정의합니다. 이진분류 모델은 각 운동 동작이 올바르게 수행되었는지(정확) 또는 잘못 수행되었는지(부정확)를 판단하는 역할을 합니다. 모바일 환경(Android)에서 실시간으로 동작해야 하며, 기존 TFLite 모델과 원활하게 통합되어야 합니다.

## Requirements

### Requirement 1: 이진분류 모델 선택 기준

**User Story:** 개발자로서, 모바일 환경에 최적화되고 기존 MS-G3D 모델과 호환되는 이진분류 모델을 선택하여 효율적인 운동 자세 평가 시스템을 구축하고 싶습니다.

#### Acceptance Criteria

1. WHEN 이진분류 모델을 선택할 때 THEN 시스템은 Android 기기에서 실시간 추론이 가능한 모델이어야 합니다
2. WHEN 모델 성능을 평가할 때 THEN 시스템은 RAM 사용량이 500MB 이하여야 합니다
3. WHEN 모델 추론 속도를 측정할 때 THEN 시스템은 단일 추론을 200ms 이내에 완료해야 합니다
4. WHEN 모델 입력 형식을 확인할 때 THEN 시스템은 MS-G3D와 동일한 포즈 데이터 형식(NTU RGB+D 25 joints)을 사용할 수 있어야 합니다
5. WHEN 모델 출력을 확인할 때 THEN 시스템은 이진 분류 결과(정확/부정확)와 신뢰도 점수를 제공해야 합니다
6. WHEN 모델 크기를 확인할 때 THEN 시스템은 TFLite 변환 후 모델 크기가 50MB 이하여야 합니다
7. WHEN 모델 배포를 고려할 때 THEN 시스템은 TensorFlow Lite 형식으로 변환 가능해야 합니다

### Requirement 2: MS-G3D + Contrastive Binary Head 평가

**User Story:** 개발자로서, MS-G3D 모델에 Contrastive Binary Head를 추가한 아키텍처의 장단점을 이해하고 프로젝트 적합성을 판단하고 싶습니다.

#### Acceptance Criteria

1. WHEN MS-G3D + Contrastive Binary Head 아키텍처를 분석할 때 THEN 시스템은 기존 MS-G3D 특징 추출기를 재사용할 수 있는지 확인해야 합니다
2. WHEN 데이터 요구사항을 확인할 때 THEN 시스템은 정확한 동작과 부정확한 동작의 쌍(pair) 데이터가 필요한지 확인해야 합니다
3. WHEN 학습 방법을 평가할 때 THEN 시스템은 Contrastive Learning 방식의 학습 복잡도를 확인해야 합니다
4. WHEN 모델 통합을 고려할 때 THEN 시스템은 기존 MS-G3D 모델과 파이프라인을 공유할 수 있는지 확인해야 합니다
5. WHEN 추론 효율성을 평가할 때 THEN 시스템은 단일 모델로 동작 분류와 이진 평가를 동시에 수행할 수 있는지 확인해야 합니다
6. WHEN 메모리 사용량을 측정할 때 THEN 시스템은 기존 MS-G3D 대비 추가 메모리 오버헤드를 확인해야 합니다

### Requirement 3: Fitness-AQA 모델 평가

**User Story:** 개발자로서, Fitness-AQA 모델의 특성과 요구사항을 이해하고 모바일 환경에서의 적용 가능성을 판단하고 싶습니다.

#### Acceptance Criteria

1. WHEN Fitness-AQA 모델을 분석할 때 THEN 시스템은 모델이 운동 품질 평가(Action Quality Assessment)에 특화되어 있는지 확인해야 합니다
2. WHEN 입력 데이터 형식을 확인할 때 THEN 시스템은 RGB 비디오 프레임을 직접 입력으로 사용하는지 또는 포즈 데이터를 사용하는지 확인해야 합니다
3. WHEN 출력 형식을 확인할 때 THEN 시스템은 이진 분류 외에 점수(score) 또는 등급(grade)을 제공하는지 확인해야 합니다
4. WHEN 모델 크기를 평가할 때 THEN 시스템은 원본 모델의 파라미터 수와 TFLite 변환 가능성을 확인해야 합니다
5. WHEN 데이터 요구사항을 확인할 때 THEN 시스템은 학습에 필요한 데이터셋 형식과 레이블 구조를 확인해야 합니다
6. WHEN 추론 속도를 측정할 때 THEN 시스템은 모바일 환경에서 실시간 처리가 가능한지 확인해야 합니다
7. WHEN 기존 시스템과의 통합을 고려할 때 THEN 시스템은 MS-G3D 포즈 추출 결과를 입력으로 사용할 수 있는지 확인해야 합니다

### Requirement 4: 데이터 요구사항 분석

**User Story:** 개발자로서, 선택한 이진분류 모델을 학습하거나 파인튜닝하기 위해 필요한 데이터의 종류와 양을 명확히 이해하고 싶습니다.

#### Acceptance Criteria

1. WHEN 데이터 형식을 정의할 때 THEN 시스템은 각 운동 동작별로 정확한 수행과 부정확한 수행 샘플이 필요함을 명시해야 합니다
2. WHEN 데이터 양을 추정할 때 THEN 시스템은 각 운동 클래스당 최소 필요한 샘플 수를 제시해야 합니다
3. WHEN 부정확한 동작 유형을 정의할 때 THEN 시스템은 일반적인 오류 패턴(예: 무릎 각도 부족, 등 굽힘 등)을 분류해야 합니다
4. WHEN 데이터 레이블링을 고려할 때 THEN 시스템은 이진 레이블(정확/부정확) 외에 추가 메타데이터가 필요한지 확인해야 합니다
5. WHEN 데이터 수집 방법을 계획할 때 THEN 시스템은 기존 공개 데이터셋 활용 가능성을 확인해야 합니다
6. WHEN 데이터 전처리를 고려할 때 THEN 시스템은 MS-G3D와 동일한 전처리 파이프라인을 사용할 수 있는지 확인해야 합니다

### Requirement 5: 모델 통합 아키텍처

**User Story:** 개발자로서, 기존 MS-G3D 동작 분류 모델과 새로운 이진분류 모델을 효율적으로 통합하여 사용자에게 통합된 피드백을 제공하고 싶습니다.

#### Acceptance Criteria

1. WHEN 모델 통합 방식을 설계할 때 THEN 시스템은 순차적 추론(분류 → 이진평가) 또는 병렬 추론 방식을 선택해야 합니다
2. WHEN 포즈 데이터를 처리할 때 THEN 시스템은 두 모델이 동일한 포즈 시퀀스를 공유하여 중복 처리를 방지해야 합니다
3. WHEN 추론 결과를 결합할 때 THEN 시스템은 동작 클래스와 정확도 평가를 함께 사용자에게 표시해야 합니다
4. WHEN 성능을 최적화할 때 THEN 시스템은 두 모델의 총 추론 시간이 400ms 이하여야 합니다
5. WHEN 메모리를 관리할 때 THEN 시스템은 두 모델을 동시에 메모리에 로드했을 때 총 RAM 사용량이 800MB 이하여야 합니다
6. WHEN 오류를 처리할 때 THEN 시스템은 한 모델의 실패가 다른 모델의 동작에 영향을 주지 않아야 합니다

### Requirement 6: 사용자 피드백 인터페이스

**User Story:** 사용자로서, 내가 수행한 운동 동작이 어떤 운동인지뿐만 아니라 올바르게 수행했는지에 대한 명확한 피드백을 받고 싶습니다.

#### Acceptance Criteria

1. WHEN 실시간 인식 화면에서 THEN 시스템은 운동 클래스와 함께 정확도 평가(정확/부정확)를 표시해야 합니다
2. WHEN 부정확한 동작이 감지되면 THEN 시스템은 시각적 경고(예: 빨간색 표시)를 제공해야 합니다
3. WHEN 정확한 동작이 감지되면 THEN 시스템은 긍정적 피드백(예: 초록색 표시)을 제공해야 합니다
4. WHEN 신뢰도가 낮을 때 THEN 시스템은 불확실성을 사용자에게 알려야 합니다
5. WHEN 동영상 분석 결과를 표시할 때 THEN 시스템은 전체 동영상에 대한 정확도 통계를 제공해야 합니다
6. WHEN 사용자가 결과를 확인할 때 THEN 시스템은 개선이 필요한 부분에 대한 간단한 힌트를 제공해야 합니다

### Requirement 7: 모델 성능 벤치마킹

**User Story:** 개발자로서, 선택한 이진분류 모델의 실제 성능을 다양한 Android 기기에서 측정하고 최적화 필요성을 판단하고 싶습니다.

#### Acceptance Criteria

1. WHEN 모델 성능을 테스트할 때 THEN 시스템은 최소 3가지 다른 사양의 Android 기기에서 벤치마크를 수행해야 합니다
2. WHEN 추론 시간을 측정할 때 THEN 시스템은 평균, 최소, 최대 추론 시간을 기록해야 합니다
3. WHEN 메모리 사용량을 측정할 때 THEN 시스템은 모델 로드 시와 추론 시의 메모리 사용량을 구분하여 측정해야 합니다
4. WHEN 배터리 소모를 평가할 때 THEN 시스템은 1시간 연속 사용 시 배터리 소모율을 측정해야 합니다
5. WHEN 정확도를 평가할 때 THEN 시스템은 테스트 데이터셋에서 정밀도(Precision), 재현율(Recall), F1 점수를 계산해야 합니다
6. WHEN 최적화를 고려할 때 THEN 시스템은 양자화(Quantization) 또는 프루닝(Pruning) 적용 가능성을 평가해야 합니다

### Requirement 8: 배포 및 유지보수

**User Story:** 개발자로서, 이진분류 모델을 안정적으로 배포하고 향후 업데이트를 용이하게 관리할 수 있는 구조를 만들고 싶습니다.

#### Acceptance Criteria

1. WHEN 모델을 배포할 때 THEN 시스템은 모델 파일을 앱 assets에 포함하거나 원격 다운로드 방식을 선택해야 합니다
2. WHEN 모델 버전을 관리할 때 THEN 시스템은 모델 파일명에 버전 정보를 포함해야 합니다
3. WHEN 모델을 업데이트할 때 THEN 시스템은 기존 모델과의 호환성을 유지하거나 마이그레이션 전략을 제공해야 합니다
4. WHEN 오류가 발생할 때 THEN 시스템은 모델 로드 실패 시 폴백(fallback) 동작을 정의해야 합니다
5. WHEN 모델 성능을 모니터링할 때 THEN 시스템은 실제 사용 환경에서의 추론 시간과 오류율을 로깅해야 합니다
6. WHEN 사용자 피드백을 수집할 때 THEN 시스템은 잘못된 평가에 대한 사용자 신고 기능을 제공해야 합니다
